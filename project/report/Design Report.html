SECTION 01

Introduction

College0 is an AI-enabled online college program management system for a small graduate school of approximately 47 students, 12 instructors, and a single registrar. The system supports four distinct user roles — Registrar, Instructor, Student, and Visitor — and organises each academic term into four managed phases.

This document provides the full data structure, logic, use cases, entity model, and pseudo-coded methods needed to implement College0. It is the primary reference for the implementation team.

1.1 System Architecture Overview

College0 is a single-window GUI application (web-based SPA or equivalent desktop shell). All state is held in a relational store. An AI subsystem runs locally with a vector database seeded from the college handbook and registrar memos; queries that cannot be answered locally are escalated to an external LLM with a hallucination warning.

LayerTechnology choiceResponsibility
PresentationReact SPA (single window)All GUI screens; no pop-up windows
State / BLLIn-memory store + service layerAll business rules, role enforcement
PersistenceRelational DB (SQLite or PostgreSQL)All entities per Section 3
AI subsystemVector DB (local) + external LLM APIContext-aware Q&A per role

1.3 Core Business Rules

BR-01A student must register for 2–4 courses per semester. Fewer than 2 triggers a system warning.
BR-02Courses with fewer than 3 enrolled students are cancelled after the registration period; affected students receive a special registration window.
BR-03Any student with cumulative GPA < 2.0, or who has failed the same course twice, is automatically terminated.
BR-04Students with cumulative GPA between 2.0–2.25 receive a warning and must interview the registrar.
BR-05Semester GPA ≥ 3.75 or cumulative GPA > 3.5 (after ≥ 2 semesters) earns honor-roll status; one honor retires one warning.
BR-06Reviews are anonymous to everyone except the registrar. 1–2 taboo words → masked + 1 warning to author. ≥ 3 → hidden + 2 warnings.
BR-07Any instructor whose class average rating < 2.0 receives a warning. Three cumulative warnings → suspension for next semester.
BR-08Instructors whose class GPA is above 3.5 or below 2.5 must justify to the registrar; unjustified → warning or immediate termination.
BR-09Any instructor who did not post all grades by end of grading period receives a warning. All courses cancelled → instructor suspended.
BR-10Graduation requires completion of 8 classes and registrar confirmation of all required courses. Reckless application → 1 warning.
BR-11A student may retake a class only if they received an F in a previous attempt.
BR-12Students with ≥ 3 warnings are suspended for one semester and must pay a fine to the registrar.

Use Cases

Each use case is described with actors, preconditions, a normal scenario, one or more exceptional scenarios, and postconditions.

UC-01 · Apply for Admission

UC-01-N · Normal Scenario
Apply for Admission
Actors: Visitor | System | Registrar (async)
PreVisitor is unauthenticated. Registration quota not full.
Step 1Visitor opens Apply form, selects type: Student or Instructor.
Step 2Visitor provides full name, email, prior GPA (student), and statement.
Step 3System stores Application record with status = PENDING.
Step 4System auto-screens: if student with GPA > 3.0 and quota open → status = AUTO_ACCEPTED.
Step 5System emails temporary credentials (student ID + temp password). Student must change password on first login.
PostStudent account created, isActive = TRUE, firstLogin = TRUE.
UC-01-E · Exceptional Scenarios
Apply for Admission
Actors: Visitor | System | Registrar
E1: Low GPAGPA ≤ 3.0 → status = PENDING_REGISTRAR. Registrar must decide manually and must provide written justification if rejecting a high-GPA applicant or accepting a low-GPA one.
E2: Quota fullEven if GPA > 3.0, quota reached → routed to registrar. Registrar may reject without justification.
E3: Instructor appInstructor applications always go to registrar (no auto-accept). Approval assigns class(es); rejection needs no justification.
E4: Duplicate emailSystem detects existing account for email → rejects with "Account already exists."
Post (E)Application stored; applicant notified of outcome or pending status.

SECTION 04

Detailed Design

Pseudo-code is provided for every major system method. Conventions: → returns, RAISE throws an application error, DB.* denotes data-access operations.

Naming: methods prefixed with check* are triggered automatically by the system (no user action required). Methods prefixed with process* require registrar action.
applyForAdmission INPUT: name, email, type, priorGpa?, statement? → Application
METHOD applyForAdmission(name: String, email: String, type: Enum{student|instructor}, priorGpa: Decimal?, statement: String?) → Application // Validate inputs IF DB.USER.exists(email) THEN RAISE "Account already exists for this email" IF type == "student" AND priorGpa IS NULL THEN RAISE "GPA required for student application" IF name.length == 0 OR email.length == 0 THEN RAISE "Name and email are required" app ← DB.APPLICATION.create({name, email, type, priorGpa, statement, status: "PENDING", createdAt: NOW()}) // Auto-screening for student applications only IF type == "student" THEN quota ← DB.STUDENT.count(isActive: TRUE) < SYSTEM.MAX_STUDENTS IF priorGpa > 3.0 AND quota THEN app.status ← "AUTO_ACCEPTED" _createStudentAccount(app) ELSE app.status ← "PENDING_REGISTRAR" notifyRegistrar(app) END IF ELSE // instructor — always goes to registrar app.status ← "PENDING_REGISTRAR" notifyRegistrar(app) END IF DB.APPLICATION.save(app) RETURN app PRIVATE METHOD _createStudentAccount(app: Application) → Student tempPassword ← generateSecureToken(16) user ← DB.USER.create({username: deriveUsername(app.name, app.email), email: app.email, passwordHash: bcrypt(tempPassword), role: "student", isActive: TRUE, firstLogin: TRUE}) studentID ← "s-" + zeroPad(DB.STUDENT.nextSequence(), 5) student ← DB.STUDENT.create({studentID, userID: user.userID, gpa: 0.0, completedClasses: 0, honorCount: 0, isTerminated: FALSE}) emailCredentials(app.email, studentID, tempPassword) RETURN student
processApplication INPUT: registrarId, applicationId, decision, justification? → void
METHOD processApplication(registrarId: UUID, applicationId: UUID, decision: Enum{accept|reject}, justification: String?) reg ← DB.REGISTRAR.find(registrarId) or RAISE "Unauthorised" app ← DB.APPLICATION.find(applicationId) or RAISE "Application not found" IF app.status NOT IN ["PENDING_REGISTRAR"] THEN RAISE "Application already processed" // Rule-deviation guard: justify if deviating from GPA rule IF app.type == "student" THEN quota ← DB.STUDENT.count(isActive: TRUE) < SYSTEM.MAX_STUDENTS ruleWouldAccept ← app.priorGpa > 3.0 AND quota IF (decision == "reject" AND ruleWouldAccept) OR (decision == "accept" AND NOT ruleWouldAccept) THEN IF justification IS NULL OR justification.length < 20 THEN RAISE "Justification required when deviating from GPA / quota rule" END IF END IF END IF app.status ← decision == "accept" ? "ACCEPTED" : "REJECTED" app.justification ← justification app.processedBy ← registrarId app.processedAt ← NOW() DB.APPLICATION.save(app) IF decision == "accept" THEN IF app.type == "student" THEN _createStudentAccount(app) ELSE _createInstructorAccount(app) END IF END IF notifyApplicant(app)
registerCourses INPUT: studentId, semesterId, courseIds[] → RegistrationResult
METHOD registerCourses(studentId: UUID, semesterId: UUID, courseIds: UUID[]) → RegistrationResult student ← DB.STUDENT.find(studentId) or RAISE "Student not found" sem ← DB.SEMESTER.find(semesterId) or RAISE "Semester not found" IF sem.currentPhase NOT IN [2, 2.5] THEN // 2=registration, 2.5=special RAISE "Registration is not open in the current semester phase" IF student.isSuspended OR student.isTerminated THEN RAISE "Suspended or terminated students may not register" IF courseIds.length < 2 OR courseIds.length > 4 THEN RAISE "Must register for 2 to 4 courses" enrollments ← [] registeredSlots ← [] // [{day, start, end}] for conflict detection FOR EACH cid IN courseIds DO course ← DB.COURSE.find(cid) or RAISE "Course " + cid + " not found" IF course.status == "CANCELLED" THEN RAISE cid + " is cancelled" // Retake guard prior ← DB.ENROLLMENT.find(studentId, cid, status: "graded") IF prior EXISTS AND prior.grade != "F" THEN RAISE "Cannot retake a passed course" // Time conflict check FOR EACH slot IN registeredSlots DO IF overlaps(course.schedule, slot) THEN RAISE "Time conflict between " + cid + " and existing selection" END FOR registeredSlots.append(course.schedule) // Capacity check IF course.enrolled >= course.capacity THEN RETURN {type: "WAITLIST_OFFER", courseId: cid} END IF enrollment ← DB.ENROLLMENT.create({studentId, courseId: cid, semesterId, status: "ENROLLED", registeredAt: NOW()}) course.enrolled++ DB.COURSE.save(course) enrollments.append(enrollment) END FOR RETURN {type: "SUCCESS", enrollments}
addToWaitList INPUT: studentId, courseId → WaitListEntry
METHOD addToWaitList(studentId: UUID, courseId: UUID) → WaitListEntry IF DB.WAITLIST.exists(studentId, courseId) THEN RAISE "Already on wait-list for this course" position ← DB.WAITLIST.count(courseId) + 1 entry ← DB.WAITLIST.create({studentId, courseId, position, addedAt: NOW()}) notifyStudent(studentId, "You are #" + position + " on the wait-list for " + courseId) RETURN entry
processWaitListEntry INPUT: instructorId, waitlistId, decision → void
METHOD processWaitListEntry(instructorId: UUID, waitlistId: UUID, decision: Enum{admit|skip}) wl ← DB.WAITLIST.find(waitlistId) or RAISE "Wait-list entry not found" ins ← DB.INSTRUCTOR.find(instructorId) IF ins.courseIds NOT CONTAINS wl.courseId THEN RAISE "Instructor does not teach this course" IF decision == "admit" THEN // Check student won't exceed 4-course cap currentCount ← DB.ENROLLMENT.count(wl.studentId, status: "ENROLLED") IF currentCount >= 4 THEN RAISE "Student already enrolled in 4 courses" enrollment ← DB.ENROLLMENT.create({studentId: wl.studentId, courseId: wl.courseId, status: "ENROLLED"}) DB.COURSE.incrementEnrolled(wl.courseId) DB.WAITLIST.delete(waitlistId) // Re-sequence remaining wait-list positions resequenceWaitList(wl.courseId) notifyStudent(wl.studentId, "You have been admitted to " + wl.courseId) ELSE // Skip — student stays on list, position unchanged notifyStudent(wl.studentId, "Your wait-list position for " + wl.courseId + " is unchanged") END IF
writeReview INPUT: studentId, courseId, stars, body → Review
METHOD writeReview(studentId: UUID, courseId: UUID, stars: Int, body: String) → Review enrollment ← DB.ENROLLMENT.find(studentId, courseId, status: "ENROLLED") or RAISE "Student is not enrolled in this course" IF DB.GRADE.exists(enrollmentId: enrollment.id) THEN RAISE "Reviews are closed once the instructor has posted your grade" IF DB.REVIEW.exists(studentId, courseId) THEN RAISE "You have already submitted a review for this course" IF stars NOT IN [1..5] THEN RAISE "Rating must be 1–5 stars" filterResult ← filterTabooWords(body) review ← DB.REVIEW.create({ studentId, courseId, stars, body, filteredBody: filterResult.filtered, tabooCount: filterResult.count, isVisible: filterResult.count < 3, createdAt: NOW() }) // Apply warnings to author based on taboo count IF filterResult.count >= 3 THEN issueWarning(SYSTEM, studentId, "student", "Review contained ≥ 3 taboo words") issueWarning(SYSTEM, studentId, "student", "Review hidden — 2nd warning for same review") ELSE IF filterResult.count IN [1, 2] THEN issueWarning(SYSTEM, studentId, "student", "Review contained taboo word(s)") END IF // Recompute course average and check instructor warning threshold recomputeAvgRating(courseId) course ← DB.COURSE.find(courseId) IF course.avgRating < 2.0 THEN issueWarning(SYSTEM, course.instructorId, "instructor", "Class avg rating fell below 2.0 in " + courseId) checkInstructorWarnings(course.instructorId) END IF RETURN review
filterTabooWords INPUT: text → {filtered: String, count: Int}
METHOD filterTabooWords(text: String) → {filtered: String, count: Int} tabooList ← DB.TABOO_WORD.all().map(w → w.word.toLowerCase()) words ← text.split(/\W+/) count ← 0 filtered ← text FOR EACH word IN tabooList DO pattern ← RegExp(word, "gi") matches ← text.match(pattern) IF matches THEN count ← count + matches.length filtered ← filtered.replace(pattern, "****") END IF END FOR RETURN {filtered, count}
assignGrade INPUT: instructorId, enrollmentId, letterGrade → Grade

METHOD checkStudentStanding(studentId: UUID) → StandingResult student ← DB.STUDENT.find(studentId) // Auto-termination conditions (BR-03) failedTwice ← DB.ENROLLMENT.findDuplicateF(studentId) // same course F twice IF student.gpa < 2.0 OR failedTwice THEN DB.STUDENT.update(studentId, {isTerminated: TRUE, isActive: FALSE}) notifyStudent(studentId, "Your enrollment has been terminated.") notifyRegistrar("Student " + studentId + " auto-terminated.")
